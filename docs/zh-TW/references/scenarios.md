# 常見升級情境與問答

標示說明：**[實證]** 是真實案例觀察到的；**[社群]** 是網友或論壇常見的回報，處理方式普遍有效，但需要配合實際日誌判斷。

## 1. 卡住類

### 卡在 20–30%（SafeOS 階段）很久 [實證]

先不要強制關機。這段在搬資料，速度和**項目數量**成正比，不是和資料大小成正比。

- 能回到原本系統時，檢查 `C:\Windows\SystemTemp` 的項目數。Chrome、Edge 的更新程式以 SYSTEM 身分執行，會留下大量空的 `*_url_fetcher_*` 資料夾，每天可能數十個，幾年下來可達數萬個。它們**不受 TEMP 環境變數影響**，因為 SYSTEM 身分的程式固定使用 `C:\Windows\SystemTemp`
- 其他常見的爆量來源 [社群]：`C:\Windows\Temp`、`C:\Windows\Logs\CBS`、`SoftwareDistribution\Download`、印表機 spool、舊的 Installer 快取、極大的 `$Recycle.Bin`
- 清除前先確認內容（數量、大小、日期），關閉相關程式後由使用者執行刪除

### 卡在 70–80%（第一次或第二次開機）[社群]

常見是驅動初始化。硬碟燈有閃就再等；超過 1–2 小時完全不動，才考慮強制重開，讓它回滾後再分析 Rollback 日誌。

### 無限重開、反覆回滾 [社群]

通常是 0x20017、0x30018、0x40017：開機時驅動當掉。處理順序：

1. 拔掉所有周邊，只留鍵盤、滑鼠、螢幕
2. 暫停或移除第三方防毒、加密、備份軟體的過濾驅動
3. 更新儲存控制器驅動和 BIOS
4. 拔掉沒用到的磁碟

### 黑畫面只有游標 [社群]

多半是顯示卡驅動問題（0x3000D 類型）。可以先改用內建顯示或基本顯示驅動，升級完成後再裝回。

## 2. 特定軟體與硬體

| 類別 | 為什麼有風險 | 建議 |
|---|---|---|
| 備份軟體（Acronis 等，含 `file_protector`、`snapman`、`fltsrv`、`tib_mounter`） | 檔案系統過濾驅動、快照驅動 | **先暫停即時防護**；只有日誌證實它出事才完整移除。實證案例中它全程正常 |
| 防毒 / EDR | 過濾驅動在新核心上不相容，是 0x40017 的典型原因 | 暫停或移除，升級後再裝最新版 |
| 第三方磁碟加密 | SafeOS 讀不到加密磁碟 | 先解密或暫停；BitLocker 會由安裝程式自動處理 |
| RAM disk（SoftPerfect 等） | SafeOS 裡不存在，TEMP 指過去會讓監控驅動裝不起來 | 升級前把 TEMP 和 TMP 改回 C:；升級後**重開機驗證**資料夾會自動建立，再改回去 |
| 虛擬光碟、虛擬網卡（VPN、Tailscale、虛擬機） | 額外的驅動 | 0x800F0922 時中斷 VPN；一般情況不需要移除 |
| Intel RST / RAID | SafeOS 需要對應的儲存驅動 | 更新驅動；0x20017 時優先懷疑 |
| 多顆磁碟、多個系統分割區 | 分割區分析混亂（0x…-0x20009） | 暫時拔掉舊系統碟 |
| 工程版 CPU、舊 CPU | 硬體需求檢查 | 看 `CompatData` 有沒有 Hard block；沒有就不影響 |

## 3. 升級方式的選擇

### ISO 的 setup.exe 還是 Windows Update？

- 兩者升級的核心機制相同，失敗原因也相同。Windows Update 失敗，換 ISO 通常也會失敗，要先排除原因
- **ISO 適合**：想一次升到指定版本、要無人值守（`/auto upgrade /quiet` 會自動重開機）、網路不穩
- **Windows Update 適合**：只差一個啟用套件（例如 24H2→25H2→26H2）、想要分批推送的保護
- 從 Windows Update 換成 ISO：停止 `UsoSvc`、`wuauserv`、`DoSvc`，結束 `MoUsoCoreWorker`。確認 `$WINDOWS.~BT` 沒有新的變動，代表還沒開始準備

### 掛了 ISO 為什麼還在下載？

這是動態更新，會下載最新的累積更新、安裝程式修正、相容性資料和驅動。可以用 `/dynamicupdate disable` 跳過，但裝完要再跑 Windows Update。

### 需要先下載 SetupDiag 嗎？

不一定。Rollback 日誌通常已經寫了錯誤碼和延伸碼；安裝程式失敗時也會自動跑一次，結果在 `C:\Windows\Logs\SetupDiag\`。日誌被清掉，或需要交叉比對時再下載。

## 4. 版本相關問題

### 24H2、25H2、26H2 的關係

它們共用同一代核心（build 261xx–263xx）。從同一代之間升級只需要**啟用套件**，幾分鐘、重開一次。真正費工的是從**舊一代**（例如 23H2 的 22631、Win10）完整升級。日誌裡看到 `26100.xxxx` 不代表 ISO 版本錯了，那是共用的核心版本。

### 想升 26H2，Windows Update 卻只給 25H2

26H2 是分批推送。先升 25H2，之後再套 26H2 的啟用套件，結果一樣；或直接用 26H2 的 ISO。

### 新版可以自訂使用者資料夾名稱，升級能用嗎？

不能。2026 年起，24H2 與 25H2 以後的**全新安裝**，在 OOBE 可以自訂 `C:\Users\<名稱>`。升級會沿用原本的帳號和資料夾，不會出現這個畫面，也不會有改名造成的問題。想改名的話：

- 全新安裝
- 或建立一個新的本機帳號（用想要的名字）並把資料搬過去

**不建議**直接改資料夾名稱再改 `ProfileImagePath`，很多程式寫死了舊路徑。

### 這台是全新安裝的 Win11，還是從 Win10 升上來的？

看 `HKLM\SYSTEM\Setup\Source OS (Updated on …)` 這些登錄機碼。每次完整升級都會留一筆，最早那筆的 `CurrentBuild` 就是最早的版本（10240–19045 代表 Win10，22000 以上代表 Win11）。註：登錄裡 Win11 的 `ProductName` 也常寫成「Windows 10」，這是已知的怪癖，不要用它判斷。

## 5. 遠端或無人值守升級

- 使用者不在電腦前時，用 `setup.exe /auto upgrade /quiet /eula accept`，全程不需要按按鈕。Windows Update 會停在「需要重新啟動」等人按
- 確認電源設定不會睡眠（`powercfg /requests` 會看到 SetupHost 要求系統保持清醒）
- 重開機前兆只有 `Orchestrate OS switch`，通常提早不到兩分鐘
- Claude 重開後就斷線；使用者回到桌面、重新開啟 Claude 之後，才能做升級後檢查
- 推播通知需要使用者在設定裡開啟行動推播；沒開的話只能靠對話訊息

## 6. 升級後常見現象

| 現象 | 判斷 |
|---|---|
| `Windows.old` 佔數十 GB | 正常，保留約 10 天可退回 |
| RAM disk 的 TEMP 資料夾消失 [實證] | 升級可能讓 RAM disk 軟體的設定遺失，到軟體裡重新設定開機自動建立資料夾，再重開機驗證 |
| 開機時 DNS 用戶端報「名稱解析原則表格損毀」（1023），規則的 DNS 是 100.100.100.100 [實證] | Tailscale 寫入的 NRPT 規則和開機時序衝突。DNS 正常就不需要處理 |
| `luafv` 服務被阻擋載入（7000）[實證] | 舊程式的檔案虛擬化功能，對一般使用影響小。是不是新版的普遍現象，需要進一步驗證 |
| 部分舊驅動或軟體需要重裝 | 從原廠下載支援新版的版本 |
| 隱私權設定、歡迎畫面 | 正常的 OOBE 流程 |

## 7. 乾淨開機與重試的順序

依成本由低到高排列，每做一步就重試一次，比較容易找出真因：

1. 修正日誌直接指出的問題，例如清理爆量的暫存、空間不足
2. 把 TEMP 和 TMP 改回 C:，拔除不需要的周邊和磁碟
3. 暫停第三方防毒、備份、加密軟體的即時防護
4. 乾淨開機（`msconfig` 隱藏 Microsoft 服務後全部停用，再停用所有開機項目）
5. 更新 BIOS、儲存驅動、顯示卡驅動
6. 完整移除可疑的軟體（廠商通常有專用的清除工具）
7. 最後才考慮全新安裝
